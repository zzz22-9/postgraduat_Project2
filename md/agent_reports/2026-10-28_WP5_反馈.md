应用 lifespan 持有同一 `IngestSession`、`MappingEngine(SQLiteStore)` 与 `GraphManager(SQLiteGraphStore)`；在会话的 `semantic/` 和 `graph/` 子目录独立持久化，关闭时释放连接。请求间不会重建空库。

Raw 输入必须具有 WP2 保留的 `source_payload` 与 `_ingest` 来源信息。网关重建源协议信封，调用原 Connector 复核 PNG 安全路径/哈希/可解码性、PLC 校验和设备地址、工单作用域，再完整比对重建 Raw，防止只篡改 decoded 值、对象 ID 或 message_id 绕过 WP2。随后调用 WP3 映射，将新增历史（包括图片关联的设备与工序双目标）交给 WP4 `apply_event`。

故障/恢复事件实际生成 MQTT 信号和日志，经 WP2→WP3→WP4；不直接修改图制造风险。恢复仍要求正常数值和明确恢复日志。事件限当前活动工序半开窗口，已完工或倒退注入拒收。同一 `event_id` 持久幂等，同 ID 异内容拒收。业务订单更新沿采集墙钟轨，工单沿仿真轨。

请求用本地会话锁协调；批量上限5000条。两个 SQLite 的内存检查点用于失败回滚，并恢复接入身份和内存图；重启从已处理消息及语义历史幂等补齐图。此机制用于阶段1单进程本机服务，不提供分布式事务、多 worker 同库写入或任意进程崩溃下的严格跨库原子性承诺。

## 3. 五类 API 实测

下表标准路由全部实现并测试，E2E 汇总 **38 次 HTTP 响应断言**。单元测试额外覆盖兼容路由、失败回滚、并发幂等与生命周期。

| 类别 | 方法与路径 | 已验证行为 |
|---|---|---|
| Object | `POST /api/v1/objects/ingest` | 源信封/严格Raw，单条或批量；返回七字段对象；真实经过WP2→WP3→WP4 |
| Object | `GET /api/v1/objects` | `object_id/object_type/domain/level/start/end` 过滤 |
| State | `GET /api/v1/states/{object_id}` | 最新七字段快照，不存在404 |
| State | `GET /api/v1/states/{object_id}/history` | `start/end/scope` 查询七字段状态历史 |
| Relation | `GET /api/v1/relations` | `source/target/relation/active/as_of/clock` 过滤七字段边 |
| Relation | `POST /api/v1/relations/infer` | 当前/as_of/显式对象纯推理，不暗改持久图 |
| Model | `GET /api/v1/model/graph` | 双时钟与as_of，七字段nodes/edges及层级统计、风险附加视图 |
| Model | `GET /api/v1/model/impact/{object_id}` | 正向风险、反向依赖及历史审计；不提前泄露未来恢复时间 |
| Model | `GET /api/v1/model/snapshots` | 四个已保存切片 |
| Event | `POST /api/v1/events/trigger` | 故障、恢复、业务更新；返回七字段objects/relations、impact、实际源记录与计数 |

兼容挂载 `/semantic/object`、`/semantic/objects`、`/semantic/objects/{object_id}/history`、`/relations`、`/relations/infer`、`/model/graph`、`/model/impact/{object_id}`、`/model/snapshots`。兼容写入也统一经过协调层。

正常请求200；不存在对象404；损坏PLC、PNG哈希、伪造Raw、缺来源、非法时间/活动区间等返回422且不污染正常对象与图。`start/end` 使用带时区ISO-8601；`clock=simulation` 时 `as_of` 为仿真秒，`clock=acquisition_wall_clock` 时使用ISO时间；`scope` 沿用WP3定义。
