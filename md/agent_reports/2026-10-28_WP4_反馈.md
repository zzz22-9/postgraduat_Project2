## 4. 四个切片与诊断边界

| as_of | CNC_01真实诊断 | OP20 / WO023真实状态 | 活跃风险链 | 历史风险 |
|---:|---|---|---|---|
| 59s | running | running / running | 空 | 无已解除事件 |
| 75s | fault，0x84 | running / running | CNC_01→OP20→WO023→ORDER_A | 当前事件尚未解除 |
| 95s | running | running / running | 空 | 一次[60,90)，fault_cleared |
| 360s | idle | completed / completed | 空 | 仍可审计该已解除事件 |

75秒附加风险依次为 `fault → blocked_risk → delay_risk → delivery_risk`，不写回SemanticObject；`assessment_kind="diagnostic_risk_only"`、`mes_schedule_changed=false`。OP30/OP40在早期切片为not_started，360秒两者也均completed。即使完工后人为给设备新fault，已结束执行关联也不传播到历史订单。

从ORDER_A反向查询可取得WO023、OP20/OP30/OP40、CNC_01/QC_01/MOVE_01、RES_MAT_01、LINE_01/FAC_01/ENT_01及指定时刻状态。反查保留非活动历史分配；环路测试确认终止，向上遍历同时记录cycles_detected。

双轨时钟明确隔离。仿真快照内只有身份而无该轨动态观测的ORDER_A/RES_MAT_01标为reference_only，组织标为configured；墙钟轨可查到ORDER_A的dispatched、WO023的released，后者不覆盖仿真completed。缺少早期观测的设备/工序仅使用完整身份目录中的静态关系，剥离未来动态字段并标记model_projection。

迟到标记或同对象同轨更旧时刻的事件只存审计，不覆盖实时节点；本版历史快照也排除这些迟到记录，不声称做了回溯因果修正。故障判断直接消费WP3诊断状态，不读取源信封或注入真值。

## 7. 留给WP5的10条接口约束

1. 唯一语义边界是七字段SemanticObject；唯一关系边界是七字段RelationEdge。风险、图revision、快照ID放响应包装或context，不能新增第8个对象字段。不能绕过WP2/WP3直接读transport_records生成图状态。
2. `relation_inference(objects, context=None)`是纯推理函数；传入当前对象或已按as_of选定的对象。它不由最终状态倒推过去；历史投影使用GraphManager。`process_instance_key=[work_order,process_id]`保持不变，不解析OP数字。
3. 创建`GraphManager(objects, store=SQLiteGraphStore(path), rules=rules)`，先给完整身份目录；随后`apply_event`或`replay`按WP3历史到达顺序更新。每库固定batch/epoch/scope及规则，未知身份需新注册方案或新库；重复事件返回False，内容冲突拒绝。
4. `snapshot(as_of, clock="simulation", save=False)`返回nodes/edges/level_counts/object_type_counts/risk_overlays。仿真as_of是epoch后的有限非负秒；墙钟轨用`clock="acquisition_wall_clock"`和带时区ISO时间，不混成一条时间线。
5. 身份目录只用于静态拓扑；未观测节点的model_projection必须展示为参考/未开始，不能伪称提前已有传感器读数。仿真ORDER_A/物料的reference_only不能改称订单完成或材料已消耗；真实墙钟状态另查。
6. late事件仅审计，不更新实时图，也不用于当前版本的历史重算。回放/重启幂等按持久event_id处理；网关持有同一manager并负责store关闭，不为每次请求重建空库。
7. 故障上溯调用`impact("CNC_01", 75, direction="auto")`，只沿active业务边；风险为诊断附加信息，不能改SemanticObject真实status或宣称已改变MES排程。95/360秒必须无活跃风险，同时保留已解除审计。
8. ORDER_A/WO023自动downstream，返回包含非活动历史关联的完整依赖及指定时刻状态。物料仅显式rules生成；默认演示配置是教学BOM，不是真实领料凭证。
9. 挂载`relation_service.api.create_router(lambda: manager)`和`spatiotemporal_model_service.api.create_router(lambda: manager)`；已有路径为GET /relations、POST /relations/infer、GET /model/graph、GET /model/impact/{object_id}、GET /model/snapshots。POST只返回推理结果，不暗中改图。WP5统一网关、Event接口、run_e2e_demo.py尚待实现。
10. 模型库必须是独立spatiotemporal_model.sqlite3，不写旧ERP或WP1—WP3目录。GraphStore已定义SQLite端口；Neo4j仅离线导出，嵌套属性以JSON字符串保存、值全部参数化。接入真实Neo4j前需另做连接、跨批次命名空间与实网验收；本轮没有Docker化或常驻API监听。

详细说明见[关联服务README](../../task2_1_prototype/services/relation_service/README.md)与[时空模型README](../../task2_1_prototype/services/spatiotemporal_model_service/README.md)。
