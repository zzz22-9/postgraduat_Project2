## 2. 实际执行了哪些 SQL

完整、实际执行的文件：[cleanup_demo_equipment_20261104.sql](../../minimal_factory/tools/cleanup_demo_equipment_20261104.sql)。调用时先开启外键，再用 `BEGIN IMMEDIATE` 包住整份脚本，验证后 `COMMIT`，失败 `ROLLBACK`。先在内存副本试跑，再对真实库执行。

输入是四个已核实的设备主键和名称；中间先处理引用，再删设备；输出写回同一个 `erp.db`。不是删除整个库，也不是删除订单。

核心删除语句如下，`cleanup_targets` 是脚本中建立的临时名单表，只在当前连接中使用，结束前删除：

```sql
CREATE TEMP TABLE cleanup_targets (equipment_id TEXT PRIMARY KEY, name TEXT);
INSERT INTO cleanup_targets VALUES
    ('EQ-8a51b8f87947475183cae26e535026bb', 'E-ASM-2'),
    ('EQ-ad3067b230f74f6aa5945da352c688de', 'E-MOVE-2'),
    ('EQ-abb8ea47c10f4f24b7739815640c44c6', 'E-QC-2'),
    ('EQ-f295fe048e3647d5b31cdb76315a1a3b', 'E-MOVE-1');

-- 此前先执行完整文件中的检查、归档及解除引用语句。
DELETE FROM equipment
WHERE equipment_id IN (SELECT equipment_id FROM cleanup_targets);
```

`DELETE FROM equipment` 表示删除设备表的行；`WHERE` 限定删除范围；`IN (SELECT ...)` 表示只删除名单里的四个真实主键。没有按 `EQ-%` 大范围删除。注意，`E-MOVE-2` 虽然名字像搬运，实际 `kind=inspection`；本轮没有把它的历史记到 Robot_01 上。

为什么不能只运行 DELETE：四台设备关联着 5 道已完成工序、29 条事件、1 条返修动作。已完成以下处理：

- `events`：原 `detail` 文本保留，末尾补上旧设备名称、主键和清理日期，`equipment_id` 置空。
- `operations`：仅这 5 道已完成工序的 `equipment_id` 置空。工序、状态、数量、时间和报工全部保留；旧工序详情的设备栏可能显示“未分配”，原设备身份可在该工单事件和备份中查到。
- `rework_actions`：1 条旧设备编号归档到 `note`，设备字段置空。`reworks` 本来无待删设备引用，不改。
- 其他业务表不改；外键一直开启，没有用关闭外键的方法绕过约束。

改名执行的是：

```sql
UPDATE equipment SET name = 'CNC_01 (组装/加工工位 E-ASM)' WHERE equipment_id = 'E-ASM';
UPDATE equipment SET name = 'Vision_01 (视觉质检站 E-QC)' WHERE equipment_id = 'E-QC';
UPDATE equipment SET name = 'Robot_01 (搬运机械臂 E-MOVE)' WHERE equipment_id = 'E-MOVE';
```

`UPDATE` 修改已有行；`SET name` 只改显示名称；`WHERE equipment_id` 锁定哪台设备。主键、类型、可用状态和创建时间都没变。

## 3. Python 到网页的显示链路

本轮唯一修改的业务 Python 文件是 `minimal_factory/mes/service.py`。函数 `initialize(path)` 从第 39 行开始，新增说明在 119–120 行，默认设备列表在 121–125 行，写库在 126–129 行：

```python
# 内部编号供工序分配使用；name 存入数据库并由设备页面直接显示。
# INSERT OR IGNORE 只补缺失设备，已有库的改名由一次性 SQL 完成。
for equipment_id, name, kind in [
    ("E-ASM", "CNC_01 (组装/加工工位 E-ASM)", "assembly"),
    ("E-QC", "Vision_01 (视觉质检站 E-QC)", "inspection"),
    ("E-MOVE", "Robot_01 (搬运机械臂 E-MOVE)", "transport"),
]:
    conn.execute(
        "INSERT OR IGNORE INTO equipment VALUES (?, ?, ?, 'available', ?)",
        (equipment_id, name, kind, now()),
    )
```

每个三元组的输入依次是内部编号、显示名称、工序类型。`for` 每次取一台；`?` 是 SQL 参数占位符；`now()` 提供创建时间。输出是 `equipment` 表里的默认设备行。`INSERT OR IGNORE` 只补不存在的设备，**只修改这里不会给已有数据库改名**，所以本轮另行执行 UPDATE。

显示链路是：

1. `mes/service.py:230` 的 `list_equipment(path)` 查询 `SELECT e.*`，其中包含数据库里的 `name`。
2. `mes/api.py:78` 的 `equipment()` 将结果从 `GET /mes/equipment` 返回给浏览器。
3. `web/index.html:68` 的 `refresh()` 取接口数据；第 151 行 `renderEquipment()` 使用 `<h2>${esc(e.name)}</h2>` 显示卡片标题。

没有新增 Python 前端映射函数，也没有修改 HTML；现有前端本来就支持读取名称。数据库改完后刷新即可生效。这里不读取原型的 `demo.json`。

## 5. 以后删除设备：1－2－3

1. 先备份当前库；用上面的 SELECT 找到准确主键。检查 `operations`、`reworks`、`events`、`rework_actions` 是否引用该主键。页面“设备维护”只停用设备，不删除；当前没有删除按钮或 DELETE 设备接口。
2. 在事务中处理引用后再 `DELETE FROM equipment WHERE equipment_id = '核实的主键';`。仅登记、尚未使用的 Robot_02 也会有一条登记事件，需先把它的名称和编号归档到 `events.detail` 并将事件的设备外键置空。用过的设备不能只删这一行：参照本轮完整 SQL 归档历史，且不能删除正在执行/暂停的设备，也不能悄悄把其生产历史改记到另一台。更换目标时必须重新核对名单和引用，不原样套用本次四设备名单。
3. 若删的是 `E-ASM/E-QC/E-MOVE` 这类默认种子设备，还需从 `service.py` 的 `initialize()` 列表移除对应条目，否则重启会补回；还需核对原工序的设备分配是否仍可用。网页登记的 Robot_02 不在种子列表里，不需改代码。刷新【设备资源】，再执行 `PRAGMA foreign_key_check;`（应返回空结果）确认无悬空引用。
