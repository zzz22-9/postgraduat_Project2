## 你现在怎样演示

1. 在 8000 网页按 Ctrl+F5，进入【04 设备资源】，找到 Robot_02，点【删除设备】，再点【确认删除】。页面应提示“设备已删除”，Robot_02 卡片消失。
2. 回到 VS Code 中打开的 `minimal_factory/data/erp.db`，点左上角刷新，选择 equipment。若只有三台默认设备加 Robot_02，行数应由4变3，Robot_02 对应行消失。
3. 点击 events，查看 action 为 equipment_deleted 的新日志。detail 包含删除设备的名称和完整编号。原 equipment_created 日志仍保留，补充已删除设备的身份文字，其 equipment_id 置空。

给导师讲：“网页提交删除请求后，后端删除设备表中的对应行，同时保存操作日志。现在设备表里已没有 Robot_02，事件表还能看到它的登记和删除过程。”

当前三台默认设备受到保护；已关联工序、返修任务或返修动作的设备也拒绝删除。它们保留生产记录，可使用设备维护功能。本轮不修改工艺或清理生产历史。

## 后端怎样运行

输入是你所点设备的内部编号。浏览器发送 `DELETE /mes/equipment/{eq_id}`，后端检查后操作同一个 erp.db，成功时返回设备名称、编号和 deleted=true，页面刷新列表。

- `minimal_factory/web/index.html:195`：delete-equipment 分支打开确认框，确认后调用 DELETE 接口。
- `minimal_factory/mes/api.py:93`：DELETE 路由转交 service.delete_equipment。
- `minimal_factory/mes/service.py:526`：delete_equipment 使用已有事务，读取设备、检查默认设备与生产引用、处理事件外键、删除设备并写日志。
- `minimal_factory/erp/database.py:26`：with connection 正常退出时提交，异常时回滚。

真正删除 equipment 行的代码在 service.py 第538行：

```python
conn.execute("DELETE FROM equipment WHERE equipment_id=?", (eq_id,))
```

`DELETE FROM equipment` 表示删除设备表的行；`WHERE equipment_id=?` 限定目标编号，`(eq_id,)` 把当前设备编号填进去。

下一行记录删除反馈：

```python
log(conn, "equipment_deleted", f"删除设备：{identity}")
```

设备已经删除，因此这条日志不再用外键指向它；名称和编号保存在 detail 文字里。上述删除与日志写入在同一事务中，日志写入失败时设备删除也会回滚。
