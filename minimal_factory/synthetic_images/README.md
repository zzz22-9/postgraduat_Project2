## 先看什么

打开 [六图预览](rendered_v1/preview.jpg)。每一行是一种状态，每一列是同一场景的一个视角：

| 状态 | 几何含义 | 张数 |
|---|---|---|
| unfastened / 未紧固 | 盖板已经摆放，四颗螺栓均未安装 | 2 |
| complete / 完整装配 | 四个位置均装入螺栓 | 2 |
| missing_bolt / 缺件 | 位置3缺少螺栓，其余三颗已安装 | 2 |

这里“完整”仅指四颗螺栓齐全，不证明扭矩合格或真实产品质量。三种状态是独立对照样本，不是一笔已发生订单的连续加工记录。

## 图片从哪里来

`render_assembly.py` 依次执行：

1. `scene()` 用长方体和圆柱体定义底座、盖板、中央壳体、螺栓及垫圈，按状态决定哪些螺栓出现。
2. `render()` 从固定相机发射射线，求最近的几何交点，计算表面光照和遮挡阴影，输出800×600的RGB图片。
3. 同时保存像素标签图和场景参数，再生成清单及预览。

长度采用任意场景单位；空螺孔和内六角孔的视觉效果使用深色圆形凹槽表面近似，并非真实贯穿孔或精确六角CAD结构。没有材料力学、拧紧动力学、真实相机噪声或加工物理仿真。该脚本是**图像生成组件**，SimPy仍是另外的生产事件仿真组件。

## 产物与使用方式

- `rendered_v1/images/`：6张原始PNG，无文字标签，作为后续接入或图像算法的输入。
- `rendered_v1/masks/`：6张单通道标签PNG。像素值1为工作台，2底座，3盖板，4中央壳体，5空孔，10—13分别为四个位置的螺栓组件。直接打开通常很暗，这是类别编号，不是可视化颜色。
- `rendered_v1/scenes/`：6份JSON，保存几何、相机、光源和分辨率。
- `rendered_v1/manifest.json`：样本状态、螺栓数量/位置、文件路径、SHA-256、来源和运行环境。
- `rendered_v1/validation.json`：本轮检查结果。
- `rendered_v1/preview.jpg`：带文字的六图对照，仅用于人看，不作为训练或识别输入，以免文字泄漏答案。

螺栓位置采用物体坐标：0=(-0.94, 0.58)，1=(0.94, 0.58)，2=(-0.94, -0.58)，3=(0.94, -0.58)。换视角不会改变位置编号。

数量、缺件位置和像素标签均来自场景配置，是生成真值，**不是图像算法已经识别出的结果**。本批只有6张高度相似图片，用于管线调试和理解输入，不能证明工业视觉识别的泛化能力。

## 如何重新生成

依赖见 `requirements-render.txt`；项目ERP/MES依赖没有修改。本机本轮使用已存在的Codex Python环境，无新增安装。在项目根目录的PowerShell运行：

```powershell
& 'C:\Users\18456\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -X utf8 '.\minimal_factory\synthetic_images\render_assembly.py' --verify-repeat
```

该运行环境路径可能随安装变化。也可在装有NumPy和Pillow的Python中运行同一脚本。默认重建本目录 `rendered_v1` 的生成文件；若要保留旧批次，使用新输出目录：

```powershell
python render_assembly.py --output rendered_v2 --verify-repeat
```

脚本无随机采样；在本轮相同环境下，完整装配正面图重复渲染的像素逐一相同。不同依赖/平台版本的逐字节一致性未验证。
