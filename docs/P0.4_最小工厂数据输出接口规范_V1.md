### 连接配置与现场状态

ERP/MES 由 `erp.app.create_app()` 组装，默认共享 `minimal_factory/data/erp.db`；允许传入其他路径。仿真默认根目录为 `minimal_factory/data/erp.simulations`，一般规则是 `source_path.parent / (source_path.stem + '.simulations')`，也允许显式 root。

常用启动地址为 `http://127.0.0.1:8000`；基地址是部署配置，不是“此刻在线”的保证。本轮独立客户端实际连接的是随机 loopback 端口，精确值在本机 `interface-evidence/*/http_reads.json`。2026-11-19T16:56:52+08:00 的 `netstat -ano -p tcp` 未见本机 8000/1883/4840/502 项；没有探测局域网 `192.168.10.30`，也不推断第三方服务是否存在。CIM 查询不可用，已改用 netstat。验收测试服务在退出时关闭。

当前应用没有接口认证、分页、增量游标或订阅机制。Connector 的轮询间隔、重试退避、认证和对外部署参数均待定义。建议 HTTP GET 超时后有限重试并保留上一次已校验结果；这属于调用方建议，程序未提供这些策略。业务状态更新发生于 MES/ERP 事务，接口读取是即时查询，不存在已定义的固定刷新频率。

## 2. 当前 ERP/MES/仿真 HTTP 契约

所有 GET 均无请求体；路径参数是已有 ID，表中列出的 query 是唯一已声明查询参数。成功返回 UTF-8 JSON，PNG 和指定 CSV 除外。当前路由可能忽略未声明 query，不能依赖它们实现过滤。自动文档在 `/docs`、结构在 `/openapi.json`，它们不能替代下面的业务语义。

| GET 路径 | 实际生产者 → 存储 | 成功响应与排序 | 异常/限制 |
|---|---|---|---|
| `/health` | `erp/app.py:create_app.health` | `{status:'ok',module:'erp+mes',version:'0.2.0'}` | 只表示应用存活，不保证某批次完成 |

### ERP 对象与写接口边界

Order 原始字段：`order_id:string`、`product_id:string`、`product_name:string`、`quantity:positive integer`（件）、`due_date:YYYY-MM-DD|null`、`status`、`created_at:UTC ISO8601`。Order 模型序列化 UTC 时可能使用 `Z`，数据库/feed 通常为 `+00:00`，按有时区时间解析。状态为 pending（已登记）、dispatched（已下发 MES）、in_progress（MES 开工）、completed（MES 全部工序和质量放行）。不是设备状态或检测结果。

创建链：`POST /orders → create_order → database.save_order → orders`。请求只含 product_id/product_name/quantity/due_date，201 返回 Order；非法字段/数量等返回 422。它是写接口。

`POST /orders/{order_id}/dispatch` 请求含 order_id/message_id/priority/planned_date/steps（每步 name/kind/minutes），`erp/dispatch.prepare_message` 保存原始报文后，`send_order` 真正 HTTP POST 到 `/mes/dispatch`。MES 返回关联工单，ERP 保存实际 HTTP 交互及 acknowledged_at。相同 message_id 只允许相同内容重试；冲突或状态不合法 409，通信失败 502，路径与输入 ID 不一致 422。下发/重试会写库，不能用于 Connector 读取。

发件箱条目：`message_id,order_id,timestamp,protocol,endpoint,http,payload,envelope,acknowledged_at,delivery_state,order`。protocol 为 HTTP-REST。envelope 含 `protocol/message_id/timestamp/source/target/action/http/payload`；当前 payload 为 `order_id/product_code/product_name/qty/due_date/created_at/route_steps/priority/planned_date`，route_steps 含 name/kind/minutes/equipment_id。`http` 保存 url/method/request_headers/sent_at/status_code，以及可选 response_headers/response_body/error。无真实寻址证据的旧记录不得补造。delivery_state=acknowledged 仅代表收到响应，不能等同于已完工。发件箱不是现场 MQTT 命令。

MES 的 `mes_dispatch_inbox(message_id,work_order_id,envelope_json)` 保存接收快照；通过 order_id 及该表关联订单与工单。工单产品、数量、交期优先取接收报文快照，ERP 当前 orders 行可能已经不同。取消历史可导致同一订单有多张历史工单，不得只按 order_id 随意选一张。

`DELETE /orders/{order_id}` 是永久删除写接口，已关联 MES 的订单禁止删除。本文所有读取示例都不调用写接口。

### MES 业务对象和读取链

| 数据 | 业务生产函数（`mes/service.py`，仿真另注明） | 表/事件 → 当前出口 |
|---|---|---|
| 工单和路线 | dispatch/_dispatch_legacy、update_plan、assign、release/cancel | work_orders、operations、mes_dispatch_inbox → 工单列表/详情/export |
| 设备/占用 | create_equipment、set_equipment_state、execute_operation、execute_rework | equipment + 活动 operations/reworks → `/mes/equipment`；仿真资源队列另见 events/intervals |
| 开工/暂停/恢复/报工 | execute_operation、report、log | operations、production_reports、events → 工单详情/export |
| 最终质量与返工 | inspect、create_rework、execute_rework | inspections、reworks、rework_actions、events → 工单详情/export |
| 仿真故障/维修/恢复 | `FieldRecorder.fault/recover`、`engine.simulate.processing` | 该批次 equipment/work_orders/events、summary.equipment_alerts/delay_summary → 仿真 JSON/本地 mes.db |
| MES 向设备的指令 | `engine.processing → build_mqtt_dispatch_message → FieldRecorder.message` | 沙盒 protocol_messages、MES events.detail、协议/事件 JSONL → 仿真 JSON/本地文件 |

工单标量：`work_order_id,order_id,status,priority,planned_date,created_at,released_at,completed_at,product_id,product_name,quantity,due_date,order_status,progress`。priority 为 1..3；progress 为 0..100 百分比。工单状态为 draft/released/in_progress/awaiting_quality/completed/cancelled。沙盒工单另有 planned_minutes/actual_minutes/delay_minutes/anomaly_status，不能假定正式表也有。

operations 每项有 `operation_id,work_order_id,sequence,name,kind,minutes,equipment_id,status,good_quantity,rework_attempts,started_at,completed_at,equipment_name`。kind 为 assembly/inspection/transport；minutes 为每件虚拟处理分钟，状态 pending/running/paused/completed。路线顺序为 sequence，不按时间或设备名排序。

equipment 返回 `equipment_id,name,kind,status,created_at,occupied_by,work_order_id,operation_name,operation_status`。正式 status 只有 available/maintenance，available 与 occupied_by 非空可以同时出现；沙盒另支持 fault 及 alarm_message/fault_virtual_minute/recovered_virtual_minute。summary 卡片的 status 保留发生过故障的事实，current_status 表示当前恢复状态，需分别解释。

执行数组字段及类型集中列于机器清单 `schemas.execution_records`：reports 的 good_quantity/rework_quantity、inspections 的 accepted_quantity/rework_quantity、reworks.quantity 均为整数件数；rework_actions.passed 是 SQLite 0/1 或 null。reworks 含 source_operation_id、target_operation_id、equipment_id、cycle；状态 pending/repairing/awaiting_reinspection/inspecting/completed。返修和复检属于同一 rework_id，不能把复检件数再次计入产品产出。

MES 事件字段为 `event_id:int,created_at:string,order_id,work_order_id,operation_id,equipment_id,action,operator,detail:string`。detail 可能是普通文本，也可能是 JSON 字符串；只对已知 action 解析。**它不等同于现场报文或 SimPy events.jsonl 的事件对象**。例如协议 action 为 mes_to_field_mqtt_dispatched/field_opcua_signal_reported/field_vision_http_reported/field_modbus_reported，其 detail 才是完整报文字典的 JSON 字符串。普通人工业务事件可能没有虚拟时间。

其他 MES 路由均有写入作用：POST `/mes/work-orders`（兼容下发）、`/mes/dispatch`（接收 envelope）、`/mes/work-orders/{wo_id}/release|cancel|inspections`、`/mes/operations/{op_id}/start|pause|resume|reports`、`/mes/reworks/{rework_id}/{action}`（start/finish/inspect-start/inspect-finish）、`/mes/equipment`；PATCH 工单 `plan` 和设备 `{eq_id}`；PUT 工序 `{op_id}/equipment`；DELETE 设备 `{eq_id}`。这些请求体由 `mes/schemas.py` 和 OpenAPI 定义，不是数据订阅接口。仿真 `POST /simulation/preview` 是只读预览（需 RunRequest），`POST /simulation/runs` 会创建独立批次；数据读取者不应为“刷新数据”调用它们。

## 3. 当前四种现场本地帧

生产链是 `engine.simulate.processing → field_protocols.build_* → FieldRecorder.message → SQLite/MES日志/协议JSONL/来源JSONL/SimPy事件`。本轮没有改动该链，也未改变 P0.3 写前关联检查或消息编号算法。

### 3.1 公共原始头和读取位置

每行 protocol_messages.jsonl 是一个 JSON 对象，含：

```json
{"message_id":"MSG-…","protocol":"OPC-UA","virtual_minute":6,
 "work_order_id":"WO-…","operation_id":"OP-…","equipment_id":"E-ASM",
 "device_code":"CNC_01","is_anomaly":false,"source_file":"<绝对素材路径>",
 "sample_hash":"<SHA256>","payload":{},"run_id":"SIM-…",
 "endpoint":"opc.tcp://127.0.0.1:4840/freeopcua/server/",
 "transport_mode":"local_frame","synthetic":true}
```

这是结构示意，省略号不是实际 ID。真实原始值见本轮批次和机器清单。协议取值为 MQTT、OPC-UA、Modbus-TCP、HTTP-Vision-Webhook。is_anomaly 是布尔值，SQLite 对应列为 0/1。设备绑定固定为 E-ASM→CNC_01、E-MOVE→Robot_01、E-QC→Vision_01。

相同报文还存在 `summary.protocol_messages`、该批次 `mes.db::protocol_messages.raw_json`、协议 MES 事件 detail，以及 SimPy 协议事件 detail。SQLite 表含 message_id/virtual_minute/protocol/work_order_id/operation_id/equipment_id/device_code/is_anomaly/alarm_summary/source_file/sample_hash/raw_json；**没有独立 run_id 列**，批次号在 raw_json 和目录元数据里。正式主库没有这个协议表。

message_id 是原始报文字典规范 JSON 的 SHA-256 前 32 个十六进制字符加 MSG-，其中原始路径也参与计算。读取时保留原 ID，不能因路径映射重新计算。独立 builder 可不传 run_id，仿真生产必须是当前批次真实 ID。

### 3.2 CNC：OPC UA 风格节点

实际生产者 `simulation/field_protocols.py:build_cnc_opcua_message`。素材为 `minimal_factory/synthetic_signals/generated_v1/cnc_normal.jsonl`、`cnc_overload.jsonl`，每份 12 行；sample_index 从 0 开始，仿真配置允许 0..11。manifest 的 field_library 提供整文件 SHA、阈值、单位及变换公式。

| NodeId（完整） | data_type | 素材字段 | 值/单位 |
|---|---|---|---|
| `ns=2;s=Channel1.CNC_01.SpindleCurrent` | Float | current_a | A |
| `ns=2;s=Channel1.CNC_01.MotorTemperature` | Float | temperature_c | degC（摄氏度） |
| `ns=2;s=Channel1.CNC_01.SpindleLoad` | Float | load_percent | % |
| `ns=2;s=Channel1.CNC_01.AlarmCode` | UInt16 | alarm_code | 0 正常、1 报警 |

payload 为 `{subscription_id:1,publishing_interval_ms:1000,nodes:[{node_id,data_type,value,status_code,diagnostic_info},…]}`。正常 status_code=`0x00000000 (Good)`、diagnostic_info 空字符串；异常时三个工程量节点为 `0x803C0000 (BadOutOfRange)` / `Overload`，报警码节点仍 Good。报警阈值来自 manifest：current_a>4.0、temperature_c>70.0、load_percent>80.0 任一严格超过。

索引 0 的正常原值为 3.021746 A、30.565 degC、50.362%、报警 0；异常为 5.525851 A、95.672 degC、92.098%、报警 1。它们来自合成素材实际读取，是上游合成电流确定性变换的工程量，不是真实机床传感器采集。

当前每次 processing 结束读取一次指定行，包括返修；不会自动推进 sample_index，**不是 1 秒连续采样**。素材 sample_interval_s=1 和帧 publishing_interval_ms=1000 都不证明已存在运行时发布周期。端点字段 `opc.tcp://127.0.0.1:4840/freeopcua/server/` 仅为本地帧描述，项目没有 OPC UA Server/Client 网络链路。

### 3.3 Robot：Modbus 寄存器和状态

实际生产者 `build_robot_modbus_message`，素材 `robot_normal.jsonl`、`robot_overload.jsonl` 同目录各 12 行。payload 含 unit_id（引擎默认 1，builder 允许 1..247）、function_code=3、start_address=40001、wire_start_address=0、register_count=4、raw_registers、request_frame_hex、response_frame_hex。

| 点表编号 | 线上 PDU 偏移 | 类型 | 编码/读取解码 |
|---|---:|---|---|
| 40001 | 0 | UInt16 | round(current_a×1000)；raw/1000 A |
| 40002 | 1 | UInt16 | round(temperature_c×10)；raw/10 degC |
| 40003 | 2 | UInt16 | round(load_percent×10)；raw/10 % |
| 40004 | 3 | UInt16 | alarm_code，0/1 |

采用 Python round 后整数编码，原始浮点与解码值会有量化误差；不可要求字节解码后等于未量化素材浮点。每寄存器网络大端两字节；单寄存器不涉及 Float32 字序。请求含 MBAP transaction_id=1/protocol_id=0/length=6/unit_id、FC03/offset0/count4；响应 length=11、FC03/byte_count8 和 8 个数据字节。

索引 0 正常 raw_registers=`[2417,285,604,0]`（2.417 A/28.5 degC/60.4%）；异常 `[4421,886,1105,1]`（4.421 A/88.6 degC/110.5%）。异常负载允许大于 100%。素材阈值为 3.5 A、70 degC、90%，任一严格超过报警。

没有专门的运行/待机状态寄存器。Robot 状态应读取该批次 equipment/events/equipment_alerts，并结合工序占用和命令解释，不能从电流臆测状态。端点 `modbus://192.168.10.30:502` 为描述，项目无真实 Modbus TCP Server；当前读取的是落盘帧，不向该 IP 发请求。

### 3.4 MES→三台设备：MQTT 控制命令

生产者 `build_mqtt_dispatch_message` 在每次 processing 开始产生 PUBLISH 描述，三台设备都使用，包括返修/复检。topic 为 `factory/line1/{device_code}/command`。payload 含 packet_type=PUBLISH、qos 默认 1（可 0..2）、retain=false、qos>0 时 packet_id=1、payload_json、payload_bytes_hex。payload_json 为 `{cmd:'START',wo:<工单>,op:<工序>,quantity:<本次件数>,dataset:'FIELD-ASSETS-V1'}`。

payload_bytes_hex 只编码紧凑 UTF-8 JSON 内容，**不是整个 MQTT 线上包**。packet_id=1 不可作为全局去重 ID；以 run_id/message_id 识别记录。命令的 is_anomaly=false，不预报后续故障。source_file 是对应素材 manifest，sample_hash 是清单全部字节 SHA-256；不是某个传感器样本。

描述端点 `mqtt://127.0.0.1:1883` 没有对应项目 Broker，未执行 publish/subscribe/PUBACK。不能声称 QoS1 交付成功。真正业务执行由现有 MES/SimPy 调用链完成，MQTT 本地帧是指令证据。

### 3.5 Vision：PNG 与标签检测结果

生产者 `build_vision_http_message` 真实读取 `minimal_factory/synthetic_images/rendered_v1/manifest.json` 和四个根目录 PNG：normal_front.png、normal_side.png、defect_front.png、defect_side.png。清单 `field_samples` 的 sample_id 分别为 vision_normal_front/vision_normal_side/vision_defect_front/vision_defect_side，定义图像哈希、bolt_count、view、label、source_image_path/source_sample_id。底层 images/masks/scenes 也存在，但现有 HTTP 只暴露这四个白名单 PNG。

payload 为 `{method:'POST',request_headers:{'Content-Type':'application/json'},camera_ip:'192.168.10.22',image_url:'/static/rendered_v1/normal_front.png',detections:[{label:'bolt',count:4,expected:4,PASS:true}],result_source:'scene_configuration_not_image_recognition'}`。缺陷 count=3/PASS=false/is_anomaly=true。默认 view=front，builder 也支持 side；当前仿真默认使用 front。PNG 是实际文件，sample_hash 是整 PNG SHA-256；PASS 是场景标签计数判定，不是模型识别。

在工序结束发出结果，并用公共头关联工单、工序、设备及虚拟分钟。sample_id 在 source_context；图片字节本身不嵌入本次工单 ID。camera_ip 是描述信息，不代表真实相机连接。`http://127.0.0.1:8000/mes/vision/webhook` 只是帧描述，真实路由不存在（GET 返回 404，未执行 HTTP POST 推送）。当前真实检测结果读取接口是仿真结果/JSON 导出，图片读取接口另列。

## 4. 最小关联字段和四种时间

本节只解释数据关联，不新增 Semantic Object，不修改原始协议载荷。

| 字段 | 当前实际位置 | 关联/缺失处理 |
|---|---|---|
| run_id | run.json、HTTP result、协议头、SimPy事件；input/mapping/summary 不保证顶层有 | 其余文件从所在批次获取；跨批次联合键必须含 run_id |
| message_id | 原协议、source_context、SQLite协议表；SimPy协议事件 detail.message_id；ERP收发箱也有自己的消息号 | ERP下发号与现场号不是同一命名来源；同批精确匹配，不按最近时间猜配 |
| order_id | ERP/MES、input/mapping、SimPy事件、summary.orders | 现场协议头无此字段；通过事件或工单快照取得 |
| work_order_id / operation_id | 现场头、业务表、input/mapping、事件 | 必须核对真实工单归属和当次工序 |
| equipment_id / device_code | 协议头；前者也在工序/事件；后者为固定三设备映射 | 不能把素材 template_equipment_id 当当前设备 |
| virtual_minute | 协议头、故障 detail；事件对应 sim_time_min | SimPy 分钟；同一批次可核对二者相等 |
| quantity | ERP/工单数量；MQTT payload_json.quantity；SimPy事件/intervals | CNC/Robot/Vision 原头没有；返修/复检取事件本次件数，不套整单数量 |
| phase / rework_id | SimPy事件和 intervals、沙盒返工表 | 现场原头/source_context 无；normal 的 rework_id=null，repair/reinspection 使用真实返工号 |
| source_file / sample_hash | 协议头、SQLite、source_context | 指向被消费素材；绝对路径属于生产者主机；必须实际读取并校验 |
| sample_id / sample_index | source_context；原素材行/图片清单 | 信号索引是零基；Vision 索引 null；MQTT 两者 null |
| sample_time_s | 信号素材和 source_context | 素材局部秒，当前 0..11；Vision/MQTT=null |
| source_time_s | 信号素材和 source_context | 上游合成素材秒；异常索引0为240秒；Vision/MQTT=null |

`recorded_at` 是 SimPy事件写入时的实际 UTC 墙钟时间，不是仿真时钟。MES events.created_at、订单/工单 created_at、run.created_at/finished_at、HTTP sent_at/timestamp 同属实际时间，但业务含义各自不同。input 的 order_created_at 和 work_order_created_at 分别保留原业务时间，旧 created_at 是工单时间别名；旧快照不知道订单时间时为 null，不套用工单时间或查当前主库补造。

例如本轮全故障 CNC 在虚拟第 6 分钟输出，sample_time_s=0、source_time_s=240；不能声称第 360 秒采集了上游第 360 秒的信号。当前程序没有从素材时间到 SimPy 时间的连续对齐函数，也没有真实设备 SourceTimestamp 或图像采集时间。

source_context 每行字段固定为 `message_id,source_file,sample_hash,source_kind,sample_id,sample_index,sample_time_s,source_time_s`，不带 run_id/phase。source_kind 信号/图片为 synthetic，命令为 configuration_generated。signal 的 sample_hash 是所选 JSONL 原始行去掉换行的 SHA-256，不是 json.dumps 后的哈希；Vision 为整个 PNG，MQTT 为整个 manifest。

素材信号行中的 source_file/source_sha256/source_sample_id/source_time_s 指向更上游素材；它与协议头 source_file 指向的“实际消费文件”是两级来源。本轮同时验证两级文件哈希。template_run_id 是素材历史来源，不能覆盖当前 run_id。

## 5. 批次落盘、读取状态与一致性规则

`SimulationService.start` 保存不可变 input.json、mapping.json 和 running 的 run.json，后台 `_execute → simulate` 新建 mes.db 并执行；仅成功后写 summary.json，再标记 completed。get/export 会按 completed 状态决定是否读取完整汇总。启动时将无其他执行实例持锁的旧 running 标为 interrupted，不自动续跑。

| 文件 | 原始结构与更新 | 读取注意 |
|---|---|---|
| run.json | run_id/status/created_at/finished_at/source/replay_run_id/completed_orders/total_orders/sim_time_min/error；原子替换 | 先读它，固定批次；状态可为 running/completed/failed/interrupted |
| input.json | `{source,orders:[含业务时间/路线/failure/field_protocols],equipment:[]}`，创建时一次写入 | 保留历史工单/设备身份及参数 |
| mapping.json | 数组；每项含 work_order_id/order_id/source_work_order_id/source_order_id/operations；每工序含 operation_id/equipment_id/source_operation_id/source_equipment_id | work_orders 来源保留原业务号；demo 来源 source_* 为 null；replay 仍读原 snapshot.source 决定 |
| mes.db | 本批订单、工单、工序、执行/返工/故障和协议记录 | 只读打开；不得调用 initialize/release 等业务函数获取“读取结果” |
| events.jsonl | 一行 SimPy 事件；sequence 从1递增；含 sim_time_min、recorded_at、quantity/phase/rework_id、可选 detail | 按文件顺序/sequence；同虚拟时刻允许多事件；不要按墙钟重排 |
| protocol_messages.jsonl | 一行原始本地协议头+payload | 保留文件顺序；message_id 在本批唯一 |
| source_context.jsonl | 一行 A2 来源，按 message_id 配对 | 当前 HTTP 不暴露；新完成批次必须一对一，无重复/孤立/漏项 |
| summary.json | makespan_min/orders/equipment/intervals/equipment_alerts/protocol_messages/delay_summary/completed_quantity/rework_quantity/total_waiting_min/event_count | 仅 completed 可当最终结果；无顶层 run_id，必须保留目录上下文 |

正常及返工读取规则：completed 且完整汇总可解析，消息/来源精确一对一，输入→工单→工序→设备正确；协议 JSONL、SQLite raw_json、MES协议 detail、SimPy协议 detail、summary 内协议应一致。repair/reinspection 必须通过 events 或 intervals 关联真实 reworks 及本次 quantity，不能因同工序多次出现判为重复。资源共享可能使不同工单交织；按 ID 与 sequence 关联。

运行中/失败/中断：JSONL 可有合法前缀，HTTP get 只解析以换行结束的完整行；非 completed 的 summary=null，equipment_alerts/delay_summary 缺汇总时为 []，并不代表未发生故障。不得把前缀提升为完成数据；summary_csv 会拒绝。Connector 应把前缀标为 partial，并保留 error/status。完成批次缺文件、坏 JSON 或跨通道不一致属于异常，不能静默回退到“完成”。当前服务未统一包装损坏文件错误，可能返回 500，读取方应报告损坏。

各输出跨 SQLite/多个文件不是一个原子事务；P0.3 写前检查拒绝关系错误，不保证磁盘故障时多通道原子完成。完成后做独立一致性校验才能接受为完整批次。

历史兼容：已知正式旧批次 `SIM-50cb01e187b741adadf46f023144df4f` 缺 source_context（本轮只读复核，原数据保留）。按原 run/input/summary/协议继续读取，明确标记 A2 追溯不可用；不回填旧文件、不猜素材时间、不因缺 A2 单独否决已知旧批次。对新批次缺文件则报告缺失；缺失本身不足以判定“这是旧批次”。

## 6. 最小可复制读取示例

以下示例只用 Python 标准库。输入为**已启动的服务地址**或**已存在的批次路径**，不创建订单或仿真。以项目根目录为当前目录执行；跨机器需映射素材路径，见示例后说明。

### HTTP：订单→工单→结果→PNG

把以下代码保存到任意临时脚本执行。可用环境变量 FACTORY_BASE_URL 指向实际服务；此处默认值只是启动惯例。

```python
import hashlib, json, os
from urllib.request import ProxyHandler, build_opener

base = os.environ.get('FACTORY_BASE_URL', 'http://127.0.0.1:8000').rstrip('/')
client = build_opener(ProxyHandler({}))
def get(path):
    with client.open(base + path, timeout=10) as response:
        return json.load(response)

print(get('/health'))
orders = get('/orders')
work_orders = get('/mes/work-orders')
if orders:
    order = get('/orders/' + orders[0]['order_id'])
    related = [w for w in work_orders if w['order_id'] == order['order_id']]
    for w in related:
        trace = get('/mes/work-orders/' + w['work_order_id'] + '/export')
        print(trace['work_order']['work_order_id'], trace['work_order']['status'])
print(get('/erp/feed')['dispatch_outbox'])

completed = [r for r in get('/simulation/runs') if r['status'] == 'completed']
if completed:
    run = get('/simulation/runs/' + completed[0]['run_id'] + '/export?format=json')
    assert run['summary'] is not None
    for m in run['protocol_messages']:
        if m['protocol'] == 'HTTP-Vision-Webhook':
            with client.open(base + m['payload']['image_url'], timeout=10) as response:
                png = response.read()
            assert png.startswith(b'\x89PNG\r\n\x1a\n')
            assert hashlib.sha256(png).hexdigest() == m['sample_hash']
            print(m['message_id'], m['payload']['detections'])
```

列表空是正常结果；不要为获取样例而写正式库。未知订单或工单返回 HTTPError 404，非法 format 返回 422，非完成 summary_csv 返回 409，均含 FastAPI detail。应用没有 GET 协议推送地址 `/mes/vision/webhook`，不可用它取检测结果。

### 文件：协议→来源→业务上下文

先指定一个真实完成批次（环境变量 FACTORY_RUN_DIR 必填）。本轮可使用验收报告列出的 `.task_work/p04_20261119/real-runs/SIM-…`，正式默认根目录为 minimal_factory/data/erp.simulations。下面不导入 builder。

```python
import hashlib, json, os
from pathlib import Path

folder = Path(os.environ['FACTORY_RUN_DIR'])
meta = json.loads((folder / 'run.json').read_text(encoding='utf-8'))
if meta['status'] != 'completed':
    raise RuntimeError('批次不是完成结果: ' + meta['status'])
def rows(name):
    raw = (folder / name).read_bytes()
    assert not raw or raw.endswith(b'\n'), '完成批次尾行不完整'
    return [json.loads(line) for line in raw.splitlines()]

messages, events = rows('protocol_messages.jsonl'), rows('events.jsonl')
summary = json.loads((folder / 'summary.json').read_text(encoding='utf-8'))
assert messages == summary['protocol_messages']
source_path = folder / 'source_context.jsonl'
sources = rows('source_context.jsonl') if source_path.exists() else None
if sources is None:
    raise RuntimeError('缺A2：先确认旧批次兼容资格；原协议仍可单独读取')
by_id = {s['message_id']: s for s in sources}
assert len(by_id) == len(sources) == len(messages)
assert set(by_id) == {m['message_id'] for m in messages}
contexts = {}
for event in events:
    detail = event.get('detail')
    if isinstance(detail, dict) and 'message_id' in detail and 'payload' in detail:
        assert detail['message_id'] not in contexts
        contexts[detail['message_id']] = event
for m in messages:
    s, e = by_id[m['message_id']], contexts[m['message_id']]
    assert m['run_id'] == e['run_id'] == meta['run_id']
    assert m['virtual_minute'] == e['sim_time_min']
    assert all(m[k] == e[k] for k in ('work_order_id', 'operation_id', 'equipment_id'))
    assert s['source_file'] == m['source_file'] and s['sample_hash'] == m['sample_hash']
    raw = Path(s['source_file']).read_bytes()
    selected = raw.splitlines()[s['sample_index']] if s['sample_index'] is not None else raw
    assert hashlib.sha256(selected).hexdigest() == s['sample_hash']
    if s['sample_index'] is not None:
        sample = json.loads(selected)
        assert all(sample[k] == s[k] for k in ('sample_id','sample_index','sample_time_s','source_time_s'))
    print(m['protocol'], e['order_id'], e['quantity'], e['phase'], e['rework_id'],
          m['virtual_minute'], s['sample_time_s'], s['source_time_s'])
```

该示例在来源缺失时保留“未完成验证”的明确结果；完整验收还应核对 input/mapping/SQLite 关系，已实现于 `minimal_factory/tests/test_output_contract.py:read_batch`。仿真事件 CSV 未包含 detail，不能代替上述 JSONL。

只读 SQLite 示例：

```python

from pathlib import Path
path = Path(os.environ['FACTORY_RUN_DIR']) / 'mes.db'
with closing(sqlite3.connect(path.resolve().as_uri() + '?mode=ro', uri=True)) as conn:
    conn.execute('PRAGMA query_only=ON')

```

当前 source_file 保存生产者主机绝对路径，远端开发者不能直接用自己的 Path 打开。当前 V1 完整追溯要求同机/挂载素材；跨机器可由操作方提供旧根→新根显式映射，确认仍在素材根内并校验原始哈希，保留原路径及 message_id。不能把任意本地路径交给图片 HTTP 路由。通用素材下载/可移植清单发布目前未实现，是后续明确事项。

## 7. 未来目标接口与连续多模态扩展（尚未实现）

ERP/MES 的既有只读 HTTP 可直接作为未来 Connector 输入，本轮不新建服务层。下列均为 P1/P2 设计要求，地址/认证/发布周期除已说明建议外一律待定义，不能使用本地帧 endpoint 冒充可用服务。

| 对象 | 目标接口建议 | 验收前必须实现并真实验证 |
|---|---|---|
| CNC | 真实 OPC UA Server 暴露上述节点类型/单位，Client 读或订阅；业务关联作为明确元数据/旁路记录 | 生命周期、namespace URI/稳定节点身份、安全证书/认证、真实 SourceTimestamp/质量、连续采样与历史查询；ns=2 不是跨部署稳定 namespace 身份 |
| Robot | 真实 Modbus TCP Server，建议保持 Unit1/FC03/offset0..3/UInt16 缩放 | 主机端口与轮询周期、整组寄存器一致快照、溢出/通信失败行为；状态扩展点表另行版本化；寄存器缺业务时间和 ID，需旁路关联输出 |
| MES 命令/设备状态 | 真实 Broker、Publisher、Subscriber；建议保留命令 topic、QoS1、retain=false；状态/遥测另定 topic | TLS/认证、断线重连、确认/重试、幂等去重和留存；按显式新版契约加入 run_id/message_id/执行上下文，保持 V1 原始载荷不变 |
| Vision | 复用四 PNG GET；实现版本化结果查询/推送，图像与结果按不可变身份和哈希关联 | 实际结果服务路由/方法、推送或轮询模式、认证/幂等/重试、图像留存和采集时间；若要模型识别，另实现推理及 model/version，不得沿用标签回放冒称推理 |

连续多模态输出的最小扩展要求：

- 每条连续样本保留现有 run_id、设备/工单/工序、source_file/hash 和来源时间；建议新增 schema_version、stream_id、sample_sequence、sample_period_s、质量/缺失原因，并明确 idle 时业务 ID 可空的规则。当前没有这些流字段。
- 同设备同流按 `(run_id,equipment_id,stream_id,sample_sequence)` 排序；message_id 用于记录去重；不同模态通过同批业务 ID、phase/rework_id 和明确时间窗口关联，不能把同一虚拟时刻直接当成同一样本。
- 建议增加 virtual_time_s=virtual_minute×60 作为单位明确的派生值；素材回放需显式定义原点和速率，例如 `virtual_start_s + (sample_time_s - asset_start_s) / replay_rate`。这是未来设计，当前没有该连续映射；source_time_s 仍保留上游原值。
- 实时网络订阅需规定顺序、重复/迟到、断线恢复和状态变化；历史读取继续以不可变批次 manifest/JSONL/汇总为基础，并明确传输完成标志和来源文件可移植寻址。实时成功不能替代历史完整性检查。
- CNC 故障导致连续信号变化、Robot 连续状态、Vision 图像/结果采集、与故障/返工窗口一致的多模态生成仍待 P1/P2。本轮只验证已有离散样本驱动的故障、维修、返工和恢复级联。
